Running and Testing a Website

Understand local HTTP servers vs the file:// protocol, cross-browser verification, mobile viewport checks, and W3C validation workflows.

Protocol

http:// vs file://

Localhost

127.0.0.1:3000 / 5500

Validation

W3C HTML / CSS Checker

Estimated Time

30 Minutes

1. Why You Need a Local Server

Double-clicking an HTML file opens it in your browser with the file:/// protocol. While simple, file:/// blocks modern web features like web fonts (CORS restrictions), JavaScript ES modules (import/export), and Fetch API requests due to browser security sandboxes.

Running via a local HTTP server (like VS Code Live Server or Node/Vite) serves pages over http://localhost:port, exactly replicating how production web hosts behave.

2. The Testing Checklist

  • Cross-Browser: Test your pages on Chromium (Chrome/Edge), Gecko (Firefox), and WebKit (Safari).
  • Responsive Breakpoints: Test at 360px (mobile), 768px (tablet), 1024px (laptop), and 1440px+ (desktop).
  • Console Cleanliness: Ensure 0 red JavaScript errors or 404 missing resource warnings in the DevTools Console.
  • Cache Invalidation: Use Ctrl+Shift+R (or Cmd+Shift+R on Mac) to bypass the browser cache and load fresh assets.

3. Code Example: Testing Meta & Title

<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>My Tested Website</title>
</head>
<body>
    <p>Server verified and ready for deployment!</p>
</body>
</html>
